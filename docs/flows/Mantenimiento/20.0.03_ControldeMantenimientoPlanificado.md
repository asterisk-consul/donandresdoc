# Control de Mantenimiento Planificado

## Objetivo

El proceso de **Control de Mantenimiento Planificado (CMP)** permite registrar, dar seguimiento y ejecutar tareas de mantenimiento sobre unidades, asegurando su trazabilidad y priorización dentro del sistema.

## Pantalla Principal: Detalle de la Solicitud

Esta pantalla se divide en secciones lógicas para garantizar que se capture toda la información necesaria sobre la tarea de mantenimiento.

### 1. Datos de la Solicitud (Identificación de la Tarea)

| Campo               | Descripción del Dato                                                  | Notas Importantes                                                                             |
| ------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| ID                  | Número interno único de identificación del registro (ejemplo: 18233). | Generado automáticamente por el sistema. Sirve para referencia interna.                       |
| Solicitud N°        | Número de la solicitud cargada (ejemplo: 475).                        | Número de referencia externo o asociado a un formulario de solicitud de mantenimiento previo. |
| Fecha que se cargó  | Fecha de creación automática del registro (ejemplo: 26/09/2025).      | Si se cargo en el anterior ya viene cargado.                                                  |
| Fecha de compromiso | Fecha límite o prevista de ejecución.                                 | Se selecciona desde el calendario. Define el target (objetivo) de finalización de la tarea.   |
| Referencia          | Breve descripción de la tarea (ejemplo: ACOMODAR ZÓCALOS).            | Título corto y descriptivo que permite identificar rápidamente la tarea en listados.          |
| Unidad              | Unidad o equipo al que corresponde la tarea (ejemplo: OPC575).        | Dato obligatorio. Ingresar todo junto la patente.                                             |

### 2. Priorización y Responsable

| Campo      | Descripción del Dato                                                              | Notas Importantes                                                                                                   |
| ---------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Prioridad  | Nivel de importancia de la solicitud (ejemplo: Alta, Media, Baja).                | Ayuda al planificador a ordenar y asignar recursos. Alta se reserva para tareas críticas que impactan la operación. |
| Obs Actuar | Campo para asignar un responsable o área de seguimiento (ejemplo: Flows Manager). | Asignación inicial de responsabilidad para la ejecución o seguimiento de la OT.                                     |

### 3. Notas (Detalle del Trabajo)

| Campo | Descripción del Dato                                                                            | Notas Importantes                                                                                                         |
| ----- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Notas | Detalle de las acciones a realizar (ejemplo: ACOMODAR ZÓCALOS DE ALUMINIO Y COMPRAR TORNILLOS). | Descripción exhaustiva del trabajo solicitado, incluyendo síntomas, ubicación precisa y cualquier requerimiento especial. |

### 4. Acciones Disponibles (Herramientas de Soporte)

#### ORDEN DE ABASTECIMIENTO

- Genera un pedido interno de **materiales necesarios** que están en _stock_ en almacén para realizar el mantenimiento

#### COMPRAS

- Redirige al módulo de compras para **adquirir insumos o repuestos** que _no están en stock_.

#### Seleccionar archivo para adjuntar

- Permite agregar documentación o fotos asociadas a la solicitud.

### 5. Botones de Control (Navegación y Guardado)

`CERRAR`Sale de la pantalla **sin guardar cambios**. Úsalo solo para descartar una OT que se haya iniciado por error. Se requiere confirmación para evitar pérdida de dato.

`GUARDAR` Registra la solicitud en el sistema y mantiene la pantalla actual abierta.
:::info
**Recomendación clave:** Presione **GUARDAR** periódicamente, especialmente después de cargar notas o adjuntar archivos, para asegurar el progreso.
:::
